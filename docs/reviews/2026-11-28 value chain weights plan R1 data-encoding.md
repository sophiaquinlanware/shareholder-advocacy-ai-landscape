# Value chain weights and consumer groups plan, round 1: data and encoding

Score: 64/100, REVISE.

## Top failures

1. **Line thickness mixed two incomparable things.** It put share of supplier revenue (a percent) and deal values (multi-year, "up to", sometimes stated in gigawatts) on one scale.
2. **Node size compared different segments, source firms and currencies.** Every share has the unit %, so different segments were sized against each other. Companies with no figure would have been drawn at the default size, which looks like a mid-sized company. The plan also didn't say how this fits with the existing "size = number of connections" rule.
3. **Consumer groups were named before any sourced tie, which reads as a target list.** The object of "publicly supported" was unclear. Nothing stated the guard keeping these groups out of routes and warm paths.

## Top improvements

1. Use one thickness measure, show deal values as labels, group sizes by measure, segment, source and year, and draw missing sizes hollow.
2. State whose filing counts, how parents and subsidiaries are handled, that letter-coded customers are never matched to a name, and the fiscal basis.
3. Add build checks and text equivalents in the List view.

## What was done

Revision 1 of the plan addresses each point; see the plan's "Revision 1" section. The three researchers were sent the changed rules while still working.

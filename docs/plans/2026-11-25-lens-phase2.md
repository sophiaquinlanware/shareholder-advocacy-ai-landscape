# Plan: lens system, Phase 2 (Impact investor lens)

Date: 2026-11-25. Branch: `design/lens-phase2` (from `main` at 4e96e7d, Phase 1 live). Owner: Sophia Ware. Go-ahead: "Merge and start Phase 2".

## The owner's words (Phase 2 spec, abridged)

> "Data model additions on proposal nodes (all optional, so existing data doesn't break): filing_deadline (date), agm_date (date), status ("upcoming" | "filed" | "voted" | "withdrawn" | "omitted"), vote_history: array of { year, support_pct }, seeking: array of { type: "co-filer" | "exempt solicitation" | "data" | "company relationship" | "other", note, posted_by, posted_at, verified: boolean }"

> "a) Open-window aura … a pulsing ring, plus a countdown arc that shrinks as the deadline gets close (full at 90+ days, empty at 0). Use a soft, slow pulse … Respect prefers-reduced-motion and use a static ring when it's set."
> "b) 'Seeking collaborators' aura: a second ring in a separate, clearly different color … The detail panel lists each ask as a specific line ("Needs a co-filer, posted by X, date")."
> "c) Resubmission-threshold flags … thresholds in a config constant (currently 5 / 15 / 25 percent for first, second, third+ votes) with a code comment saying to verify them against current SEC rules … If support is under the threshold, or within 3 points above it, mark the node 'At risk of losing resubmission eligibility' … ('Last vote: 14%. Needs 15% to stay eligible')."
> "d) Holdings overlay: a 'My holdings' button … the user pastes tickers … Companies they hold stay at full opacity, everything else fades to about 15%. Store it only in the client."
> "e) Gap finder: a toggle that highlights proposal topics filed at one company but not at a comparable company … Show it as a dashed 'missing' edge or a ghost node, and explain the gap in the detail panel."
> "f) Warm-path finder: in a person or org node's panel, add 'Find a path to...' which runs BFS over the people and coalition edges and highlights the shortest chain."
> "Actions block examples for this lens: 'Co-file before [date]', 'Write an exempt solicitation', 'Vote at the [date] AGM', 'Contact lead filer: [name]'."

Cross-cutting rules from the spec: no legal or regulatory facts in UI copy (rule-based values live in `rules.js` with comments); no login or backend; seeking entries come from the data file; keyboard focus on nodes; auras stated in text, not only colour; "Don't break existing tabs or URLs".

## What exists today (checked 2026-11-25)

- **No proposal has `filing_deadline`, `agm_date`, `vote_history` or `seeking`.** `meeting_date` exists on 60 of 65 proposals in proposals.json; graph.json proposal nodes carry `status`, `year`, `support_pct`, `results_url`.
- **Repeat asks are visible** but not linked: same company and subtopic in consecutive years, e.g. MSFT data-centre siting 32.03% (2024) → 27.48% (2025); META child safety 13.43% (2025) → 3.42% (2026). Whether two proposals are "substantially the same subject" is a judgement, so the UI will **not** infer `vote_history`; it reads it from data only.
- **One real resubmission exclusion is on file:** amzn-2026-responsible-ai-sales ("Excluded … as not meeting the resubmission thresholds").
- **Status values** today: voted, upcoming, excluded, withdrawn. The spec's "omitted" maps to the site's "excluded"; "filed" is new.

So every Phase 2 feature is built and tested against the owner's sample entries and test fixtures. On the live data it appears only where the data session fills the fields. The holdings overlay and warm path need no new data.

## Data contract (asked of the data session; all optional)

On proposal nodes in `graph.json` (and the matching record in `proposals.json`):
- `filing_deadline` (ISO date) + `filing_deadline_source` (URL; the proxy sentence "proposals … must be received by …").
- `agm_date` (ISO date; today's `meeting_date` is the same fact, and the UI reads either).
- `vote_history`: [{ year, support_pct, results_url }], earlier votes on the same subject at the same company, as judged and sourced by the data session.
- `seeking`: as the owner specified, plus `contact_url` (public page) instead of personal contact details.

On company nodes, optionally `next_proposal_deadline` + `next_proposal_deadline_source`: the deadline for next year's proposals, stated in the latest proxy. This lets a company show an open filing window before any proposal exists.

## `rules.js` additions (rule-based values, with comments)

- `RESUBMISSION_THRESHOLDS = [5, 15, 25]`: percent needed after the 1st, 2nd and 3rd+ vote on the same subject within the look-back period. The comment says it reflects the site's reading of SEC Rule 14a-8(i)(12) as amended in 2020 and must be verified against the current rule.
- `RESUBMISSION_LOOKBACK_YEARS = 5`, `AT_RISK_MARGIN = 3` (points above the threshold).
- `WINDOW_FULL_DAYS = 90`: the countdown arc is full at 90 or more days and empty at 0.
- `today()`: the date used for windows. It's one function so tests can fix the clock.

The vote number is 1 + the number of `vote_history` entries within the look-back. Support used is the latest `support_pct`. All wording in the UI says "under this site's reading of the resubmission rule (rules.js)", never "the SEC requires".

## Lens features (Impact investor lens only, unless noted)

1. **Open-window aura.** A node whose `filing_deadline` (or company `next_proposal_deadline`) is on or after today gets:
   - a ring in `--g-window` (green);
   - a countdown arc whose length is days left ÷ 90, capped at full;
   - a soft 4s opacity pulse, which is static under reduced motion.

   Text in the panel and List view: "Filing window open: 43 days left (deadline January 15, 2027) [source]". On the keyboard announcement: ", filing window open, 43 days left".
2. **Seeking aura.** Nodes with any `seeking` entry get a second, larger dashed ring in `--g-seeking` (amber; a different hue and dash from the window ring). The panel lists each ask: "Needs a co-filer · posted by Trillium Asset Management, January 3, 2027 · verified|not verified [contact]".
3. **Resubmission flag.** A proposal with `vote_history` or `support_pct` and a vote number gets an "At risk" check. If at risk:
   - a small badge (a short bar under the node in `--g-risk`, plus a "!" mark so it doesn't rely on colour);
   - the panel heading line "At risk of losing resubmission eligibility";
   - the action "Last vote: 14% (2026). Needs 15% to stay eligible (third vote; thresholds in rules.js)".
4. **Holdings overlay (all lenses).**
   - A "My holdings" button in the network controls opens a small panel with a textarea for tickers, comma- or newline-separated, plus Apply and Clear.
   - Kept in `localStorage["holdings"]` only, never sent anywhere; the panel says so in one line.
   - Held companies, and the proposals at them, stay at full opacity; everything else fades to 15%.
   - A count line reads: "Holdings: 4 tickers, 3 found in this map (MSFT, NVDA, AAPL); not found: XYZ."
   - The List view gets a "Held" column.
5. **Gap finder (Impact lens toggle "Show gaps").**
   - Comparable means the same primary tier (`tier`). A gap is a topic with at least one AI proposal at a company in that tier but none at another company in the same tier.
   - The check is limited to companies with proposal coverage: the original 7 the dataset tracks (value_chain.json `derived_note`). The panel says so.
   - Each gap is drawn as a ghost node, "{topic}: none filed" (hollow, dashed outline), linked to the company by a dashed "missing" edge.
   - The panel explains: "Data center impacts: 9 proposals at Microsoft and Alphabet (same tier: Hyperscalers and AI clouds), 2023–2026. None on file at Amazon."
6. **Warm-path finder.**
   - In the panel of a person or filer organisation: "Find a path to…" with a native `<select>` of companies and organisations, and a Find button.
   - It runs a breadth-first search over people and coalition edges (`works at`, `colleague`, `member of`, `coalition role`, `co-filed with`, `co-authored`, `co-presented`). A company is reached through a filing edge (`lead filer` / `co-filer` → proposal → `proposal at`).
   - The shortest chain is highlighted (other nodes fade). The panel lists each hop with its confidence marker and source link: "Trillium Asset Management → co-filed with → As You Sow (inferred from co-filing) → lead filer → Alphabet 2025: … → Alphabet".
   - "No path in this map" when none exists. Esc or Clear path ends it.
7. **Actions in the Impact lens:** the owner's examples, kept to facts and dates.
   - "Co-file before January 15, 2027" (open window, from `filing_deadline`) + source.
   - "Exempt solicitations on file: n" (Phase 1, kept). The owner's "Write an exempt solicitation" shows only on a proposal that is upcoming and whose filing has no exempt solicitation yet: "No exempt solicitation on file for this vote".
   - "Annual meeting {date}" for an upcoming vote (Phase 1 wording; it never says how to vote).
   - "Contact lead filer: {org}" with the lead filer's public profile links (Phase 1's "Public profile" list, now named from the lead filer edge).

**Wording guard** (PRODUCT.md Never claim 1–2):
- The owner's imperatives about filing ("Co-file before …", "Contact lead filer") stay; they're about filing, not voting.
- The vote line names the meeting and never a direction.
- `board_rec` is never shown in actions.
- Resubmission text names the threshold as this site's reading and never "the SEC requires".

## Revision 2 (after plan review R1: UX 68, accessibility 74, data accuracy 62; content rules failed on the gap wording, the resubmission example and exempt-solicitation asks)

These override the sections above.

**Resubmission flag (rules.js; R1 data 1, UX 1)**
- The check runs **only on a proposal node that carries `vote_history`**; it is never inferred from subtopic. On live data it shows nothing until the data session fills `vote_history`. The data session has been asked to start with msft-2026-6: 33.58% (2023), 32.03% (2024), 27.48% (2025).
- The model, as this site reads Rule 14a-8(i)(12) after the 2020 amendments:
  - For the next meeting after the latest vote, count the votes on the subject in the preceding 5 calendar years (the latest vote included).
  - The rule applies only if the latest vote was in the preceding 3 calendar years.
  - Threshold by count: 1 → 5%, 2 → 15%, 3 or more → 25%.
  - `RESUBMISSION_THRESHOLDS`, `LOOKBACK_YEARS = 5`, `RECENT_YEARS = 3` and `AT_RISK_MARGIN = 3` live in rules.js. The comment there cites 17 CFR 240.14a-8(i)(12) and says to verify it, since Rule 14a-8 changes are proposed (PRODUCT.md Never claim 8).
- **Two states:**
  - "Below this site's reading of the resubmission threshold" when support is under the threshold.
  - "At risk of losing resubmission eligibility" when support is at the threshold or no more than 3 points above it.
- **Action text:** "Last vote: 27.48% (2025). Needs 25% to stay eligible (vote 3 on this subject in 5 years)." This follows the owner's wording with the corrected threshold.
- If the latest vote has a `support_note`, it adds: "Support basis note on file: the rule counts For ÷ (For + Against); see Proposals."
- Every resubmission line ends with "(this site's reading; thresholds may change)".

**Deadline aura (R1 data 2-improvement, UX)**
- It reads the proxy's own deadline only: `filing_deadline` on proposals and `next_proposal_deadline` on companies, each with a `_source`.
- Wording: "Proposal deadline: 43 days left (January 15, 2027) [source]". The owner's "Co-file before January 15, 2027" is the action.
- The ring is called the "deadline ring" in text; there's no opening date, so no "window open".
- "Today" is the calendar date in US Eastern time (`DEADLINE_TZ = "America/New_York"` in rules.js). Days left = deadline date − today's Eastern date, and the node shows only while that is ≥ 0.
- **Pulse (R1 a11y 3):** a soft opacity pulse of 2.5s × 2 iterations (5 seconds, then it stops), meeting WCAG 2.2.2. It is off under reduced motion, and Graph settings has a "Pulse deadline rings" checkbox.

**Seeking asks (R1 UX 3)**
- Shown for types co-filer, data, company relationship and other. The **"exempt solicitation" type is not shown**: asking others to campaign on a vote is close to organising investors to vote (PRODUCT.md Never claim 1). That is recorded as an owner decision in STATE.md.
- For the same reason, the owner's example action "Write an exempt solicitation" becomes the fact "No exempt solicitation on file for this vote" (upcoming proposals only).
- Verification wording follows the site's convention: "reviewed" or "auto-detected, not yet reviewed".
- Each ask is one line: "Needs a co-filer · posted by {posted_by}, {date} · {reviewed|auto-detected, not yet reviewed} [contact]".

**Gap finder (R1 data 2, UX 2)**
- Comparability follows the owner's spec: the same node type ("Company"), and only companies with at least one AI proposal in this dataset. Today that is 7 (MSFT, GOOGL, META, AMZN, AAPL, NVDA, TSLA). It's computed from graph.json, which the network reads.
- A gap is a topic with at least one proposal at another covered company and none at this one. Live data today has 5:
  - MSFT, META and NVDA: AI governance & oversight;
  - TSLA: Data center impacts, and Social & economic impacts.
- The toggle is labelled "Show topics not filed" (`aria-pressed`). Ghost nodes are labelled "{topic}: none in this dataset". The scope is in every line: "No {topic} proposal at Tesla in this dataset (7 companies with AI proposals tracked). Filed at 5 of them: Microsoft (3), …"
- Ghost nodes are real graph nodes (kind `gap`), so they're in keyboard order and the List view. Their dashed outline is `--g-label-soft` (6.5:1).

**Warm path (R1 data improvement 1, UX improvement 2, a11y improvement 1)**
- **Edges searched:**
  - people: `works at`, `colleague`, `co-authored`, `co-presented`;
  - coalition: `member of`, `coalition role`;
  - co-filing: `co-filed with`;
  - filing, to reach companies: `lead filer`, `co-filer`, `filed (named in proxy)`, then `proposal at`.
- Breadth-first search; among equal-length paths, sourced edges are tried first.
- **Each hop is labelled.** A `co-filed with` hop reads "inferred from co-filing", linking the proposals in the edge's `proposals` list. A `member of` pair reads "shared coalition membership ({coalition}, n members)".
- **Summary line:** "Path found: 3 hops (1 inferred from co-filing, 1 shared coalition membership)". It is announced in `#net-kb`, and focus moves to the result heading (`tabindex="-1"`).
- Esc inside the panel clears the path only (it does not reach the graph's Esc), and focus returns to the Find button. "No path in this map" when none exists.

- All the new tokens are 4.5:1 or more on `--g-bg`: `--g-window` #86efac, `--g-seeking` #fda4af, `--g-risk` #fdba74.

**Holdings (R1 a11y 2, UX improvement 3)**

  - Apply and Clear buttons;
  - the line "Stored in this browser only; nothing is sent anywhere".
- **Focus:** it moves to the textarea on open; Esc closes the region and returns focus to the button.
- **Matching:** case-insensitive, against company tickers in the map.
- **Count line:** a persistent `aria-live` line, `#net-hold-status`, reads "Holdings: 4 tickers, 3 in this map (MSFT, NVDA, AAPL). Not in this map: XYZ".
- **Fading:**
  - Faded nodes stay in keyboard order, and their announcement adds "not held".
  - Labels of faded nodes are hidden, so no low-contrast text shows.
- `localStorage` reads and writes are wrapped in try/catch.
